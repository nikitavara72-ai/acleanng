# Деплой демо на Vercel

## 1. Залить

Из папки проекта:

```bash
npx vercel
```

Первый раз попросит войти — откроется браузер, авторизуешься своим аккаунтом.
Дальше на вопросы:

- `Set up and deploy?` → **y**
- `Which scope?` → твой аккаунт
- `Link to existing project?` → **n**
- `Project name?` → `chistodom` (станет `chistodom-<хеш>.vercel.app`)
- `In which directory is your code located?` → **./**
- `Want to modify these settings?` → **n**

Через пару минут в консоли появится ссылка на превью.

Когда всё устроит — боевой деплой:

```bash
npx vercel --prod
```

`output: 'standalone'` отключается сам: Vercel выставляет переменную `VERCEL=1`,
а `next.config.mjs` это ловит. Для VPS всё остаётся как было.

## 2. Переменные окружения

**Без них форма заявки вернёт ошибку.** Заказчица наверняка ткнёт в неё первым
делом — лучше настроить заранее.

В дашборде Vercel → Project → Settings → Environment Variables:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_CHAT_ID` | id чата, куда падают заявки |
| `SITE_URL` | адрес превью, например `https://chistodom.vercel.app` |

Почту (`SMTP_*`) для демо можно не подключать — хватит телеграма.

Бот делается за две минуты: @BotFather → `/newbot` → имя → получаешь токен.
Свой `chat_id`: напиши боту любое сообщение и открой
`https://api.telegram.org/bot<ТОКЕН>/getUpdates`, там будет `"chat":{"id":...}`.

После добавления переменных нужен передеплой — `npx vercel --prod`,
на лету они не подхватываются.

Заявки будут падать тебе, а не заказчице — на демо так и надо. Заодно
сильный ход на встрече: пусть заполнит форму при тебе и увидит, как
уведомление приходит мгновенно.

## 3. Закрыть демо от индексации

Пока это превью, а не боевой сайт, поисковикам его видеть не нужно —
иначе демо-домен начнёт конкурировать с будущим боевым.

В `app/robots.js` на время демо:

```js
rules: [{ userAgent: '*', disallow: '/' }],
```

Перед боевым запуском вернуть обратно.

## ⚠️ Про доступность из России

**Проверь ссылку с мобильного интернета до того, как отправишь заказчице.**

У тебя уже был случай с `m-landing.ru`: сайт на Vercel резался DPI, часть
российских пользователей его не открывала. Домены `*.vercel.app` попадают
под это регулярно.

Порядок действий:

1. Открой ссылку с телефона по мобильному интернету, без VPN.
2. Если открывается — отправляй заказчице.
3. Если нет — не отправляй ссылку вслепую, иначе она увидит белый экран
   и решит, что работа не сделана.

Запасные варианты, если Vercel не открывается:

- показать с твоего ноутбука на встрече (`npm run dev`) — для демо этого достаточно;
- поднять на Beget VPS, который уже настроен (`46.173.26.113`) — там осталось
  докрутить порт 80 снаружи;
- записать видео-прохождение по сайту и отправить файлом.

Для боевого запуска Vercel в любом случае не подходит: аудитория клининга
в Тюмени на 100% российская, риск потерять часть заявок из-за блокировки
несопоставим с удобством деплоя.

## Подключение домена chistodom.store (Reg.ru)

В коде домен уже прописан: `app/layout.js`, `app/robots.js`, `app/sitemap.js`.
Проверено — canonical, sitemap и robots отдают `https://chistodom.store`.

### 1. Добавить домен в Vercel

Project → Settings → Domains → Add. Вводишь **оба**:

- `chistodom.store`
- `www.chistodom.store`

Vercel покажет карточку с точными значениями DNS. **Бери значения оттуда.**
Раньше у всех был один A-адрес `76.76.21.21`, сейчас новые проекты получают
адрес из anycast-пула (например `216.198.79.1`). Скопируешь из старого гайда —
домен не привяжется.

### 2. Прописать записи на Reg.ru

Мои домены → chistodom.store → **DNS-серверы и управление зоной** → Управление зоной.

Сначала **удали парковочные записи** для `@` и `www`, которые Reg.ru ставит
по умолчанию — иначе они будут конфликтовать с новыми.

Потом добавь:

| Тип | Субдомен | Значение |
|---|---|---|
| A | @ | IP из карточки Vercel |
| CNAME | www | значение из карточки Vercel |

Апексу (`chistodom.store` без www) CNAME поставить нельзя: по RFC 1034
в одном узле с CNAME не может быть других записей, а там уже лежат NS и MX.
Поэтому только A.

### 3. Дождаться и проверить

Обычно 15 минут – 2 часа, изредка до суток. Проверка:

```powershell
nslookup chistodom.store
```

Должен вернуться IP из карточки Vercel. В дашборде статус домена сменится
на `Valid Configuration`, сертификат Let's Encrypt выпустится сам.

### 4. Дописать переменную и передеплоить

В Settings → Environment Variables:

```
SITE_URL = https://chistodom.store
```

Затем `npx vercel --prod` — переменные подхватываются только при новой сборке.

### 5. Выбрать основной адрес

В Domains у одного из двух будет пометка редиректа. Оставь основным
`chistodom.store`, а `www` — редиректом на него. Для поисковиков важно,
чтобы основной адрес был **один**: иначе они видят два разных сайта
с одинаковым содержимым.

## Чтобы сайт находили в поиске

Сам по себе сайт в выдаче не появится — поисковикам надо о нём сказать.

### Яндекс.Вебмастер (главное для Тюмени)

1. [webmaster.yandex.ru](https://webmaster.yandex.ru) → добавить сайт `chistodom.store`
2. Подтвердить права способом **Мета-тег**. Скопируй значение `content`
   и положи в переменную `YANDEX_VERIFICATION` на Vercel, затем передеплой.
   Тег появится в разметке сам — слот в `app/layout.js` уже есть.
3. Индексирование → Файлы Sitemap → добавить `https://chistodom.store/sitemap.xml`
4. **Настройка региона → Тюмень.** Для локального бизнеса это самое важное:
   без региона сайт не будет показываться по запросам вроде
   «клининг Тюмень», как бы хорошо он ни был сделан.

### Google Search Console

[search.google.com/search-console](https://search.google.com/search-console) →
добавить ресурс → подтвердить HTML-тегом → значение в `GOOGLE_VERIFICATION` →
передеплой → добавить sitemap.

### Сроки

Первые страницы появляются через 3–14 дней, нормальные позиции — месяцы.
Мгновенного результата не будет, заказчицу лучше предупредить сразу.

### Что даст результат быстрее, чем SEO

Для клининга в городе органический поиск — не главный канал. Быстрее сработает:

- **Яндекс.Бизнес и 2ГИС** — карточка организации со ссылкой на сайт.
  У «Чистодома» карточка в 2ГИС уже есть, надо просто добавить туда сайт.
- ссылка на сайт в шапке Telegram и WhatsApp.

### Как проверить, что бот вообще доходит

В Вебмастере → Индексирование → **Статистика обхода**. Если там ошибки
или ноль обращений через неделю — значит Яндекс-бот не достучался.
С учётом того, что Vercel у тебя режется, такой исход возможен.
Тогда переносим на Beget: меняем одну A-запись, домен остаётся тот же,
переезд минут на двадцать.

## Про сам домен

`.store` — рабочий вариант, Яндекс его индексирует наравне с остальными,
на позиции зона не влияет. Но для локальной услуги в Тюмени `.ru` читается
привычнее и вызывает больше доверия у людей. Если `chistodom72.ru` или
похожий свободен — есть смысл взять его основным позже, а `.store` поставить
редиректом. Переносить сайт при этом не придётся.

## Что показать на демо

- hero: провести курсором — кадр «протирается» из тусклого в чистый;
- калькулятор: подвигать площадь, цифра пересчитывается пружиной;
- слайдер «до/после» потянуть;
- карточки услуг: раскрыть, нажать «Рассчитать» — данные сами уезжают в форму;
- заполнить заявку и показать уведомление в телеграме.
