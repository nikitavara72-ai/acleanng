# Чистодом — одностраничный сайт

Замена tilda-сайта `chistodom72a.tilda.ws`. Next.js 16 + React 19, Framer Motion,
без внешних зависимостей и CDN — всё грузится со своего домена.

## Запуск

```bash
npm install
cp .env.example .env      # заполнить токены
npm run dev               # http://localhost:3000
```

Требуется Node.js 20+. `npm audit` должен показывать **0 уязвимостей** —
если появились, значит вышли новые advisory, обновляй сразу.

### Почему именно эти версии

Next 14 не входит в список пропатченных после декабрьских CVE 2025 года
(RCE в React Server Components, утечка исходников Server Functions, DoS) —
App Router уязвим, бэкпортов для 14.x нет. Поэтому 16.3.0.
Nodemailer подтянут до 9.x: в 6.x восемь advisory, включая SMTP command injection.

Сборка: `npm run build && npm start`

## Что уже сделано

**Палитра** — тёплый графит, слоновая кость, приглушённая шампань.
Все цвета живут в `:root` в `app/globals.css`, менять там.

**Интерактив**
- Hero: «пятно чистоты» следует за курсором (слой «до» → слой «после»), плавающие пузыри, ротация слова в заголовке
- Счётчики цифр, анимируются при попадании в экран
- Услуги: табы «дом / бизнес» с pill-анимацией + раскрывающиеся карточки (12 услуг на одной странице вместо 12 страниц)
- **Калькулятор** с живым пересчётом: услуга, слайдер площади, состояние, периодичность, допы-степперы. Число анимируется пружиной
- Слайдер «до/после» с перетаскиванием (мышь, тач, стрелки клавиатуры)
- Таймлайн процесса: линия заполняется по скроллу
- Карусель отзывов со scroll-snap, FAQ-аккордеон
- Сквозная логика: карточка услуги → калькулятор → форма заявки (данные подставляются сами)

**Бэкенд** (`app/api/lead/route.js`)
- Проверка Origin, лимит размера тела, rate-limit 5 заявок / 10 мин с IP
- Honeypot-поле + проверка времени заполнения (бот отвечает «успехом», чтобы не подбирал обход)
- Серверная валидация и нормализация телефона независимо от клиента
- Доставка параллельно в Telegram и на почту; ошибка одного канала не роняет заявку
- **Персональные данные нигде не сохраняются** — только пересылаются. Нет БД → нечего утекать

**Заголовки безопасности** (`next.config.mjs`)
CSP без внешних источников, HSTS, X-Frame-Options: DENY, nosniff, Referrer-Policy,
Permissions-Policy. `x-powered-by` отключён.

5. **Фото реальных работ** (пары до/после) → заменить файлы в `/public/works/` с теми же именами. Сейчас там сгенерированные иллюстрации интерьеров — для показа годится, для продакшена лучше настоящие объекты
6. **Фото команды и руководителя** → `/public/team/`, прописать `photo` в `lib/content.js` (`TEAM`, `DIRECTOR`). Пока `photo: null` — рендерятся инициалы

### Обработка изображений

Всё в `public/` уже пережато. Исходники были 6–9 МБ каждый (43 МБ на папку) —
для лендинга это приговор, на мобильном такое грузится десяток секунд.

- `hero.jpg` — 1920 px по ширине, JPEG q82, progressive → 255 КБ
- `works/*.jpg` — 1400 px, q80 → 110–155 КБ каждый
- `services/*.jpg` — 900 px, q80 → 39–128 КБ каждый (12 карточек услуг)
- `team/*.jpg` — 640×800, оригинальный цвет, q88 → ~57 КБ каждый

Итого папка 1,3 МБ, вся страница с кодом и картинками ~2,2 МБ.
Если будешь добавлять новые фото — прогоняй тем же способом:

```bash
convert исходник.png -resize 1400x -strip -interlace Plane \
        -quality 80 -sampling-factor 4:2:0 результат.jpg
```

### Логотип

Исходник от заказчицы — растр 63×65 px. Для шапки этого мало, для ретины
и подавно, а увеличить нечего. Поэтому знак **перерисован в вектор**:
`components/Logo.js`.

Что это даёт:

- чёткий на любом размере, от favicon до баннера;
- ~1 КБ вместо картинки, отдельного файла не нужно;
- красится через `currentColor` — сам принимает цвет родителя, поэтому
  один и тот же компонент работает и на тёмной шапке, и на светлом фоне;
- блёстки едва заметно мерцают (`animated={false}` выключает).

Экспортирует `LogoMark` (только знак) и `Logo` (знак в золотой плитке + название).
Favicon — `app/icon.svg`, та же геометрия, Next подхватывает его сам.

Форма повторяет оригинал: контур дома, труба, две четырёхлучевые блёстки.
Цвет — фирменная шампань вместо голубого, чтобы не выбиваться из палитры.
Если заказчица даст исходник в кривых (`.ai`, `.svg`, `.eps`) — можно
подменить пути в `Logo.js` на точные, всё остальное менять не придётся.

### Фото команды

Оригинальный цвет, без тонирования. Обработка только техническая: апскейл
375 px → 640×800 (Lanczos + мягкий unsharp), кроп в портрет 4:5.

Подпись с именем идёт **под** фото, а не поверх: снимки светлые, затемнять
их градиентом ради читаемости текста незачем.

**Если у заказчицы есть оригиналы с камеры — заменить на них.** Никакой
апскейл не вернёт деталей, которых нет в файле.

## Про фото людей — важное

Файлы на CDN старого сайта называются `ChatGPT_Image_15__20.png` — я сначала решил,
что портреты сгенерированы. При детальном осмотре это не подтвердилось: у людей
естественная асимметрия лица, кожа с порами и мимическими морщинами, корректно
отрисованные украшения, принт на футболке одинаково читается у всех.

Это реальная съёмка, прогнанная через нейросеть для замены фона и ретуши —
отсюда и имя файла. Фото настоящие, используем.

Правило на будущее: **сгенерированные портреты в блок команды не ставим.**
Выдавать нарисованного человека за «Ольгу со стажем 9 лет» — недостоверная
информация об исполнителе (ст. 10 ЗоЗПП), и такие лица считываются мгновенно.
Если реальных фото не будет — компонент умеет рендерить инициалы
(`photo: null` в `lib/content.js`), вёрстка не ломается.

## Настройка каналов заявок

**Telegram**: создать бота у @BotFather → `TELEGRAM_BOT_TOKEN`. Узнать ID чата:
добавить бота в группу, написать сообщение, открыть
`https://api.telegram.org/bot<TOKEN>/getUpdates` → `chat.id` (для группы — отрицательное).

**Почта Яндекс**: в настройках почты включить доступ по IMAP и создать **пароль приложения**
(не основной пароль!) → `SMTP_PASS`.

Если каналы не настроены — форма честно вернёт ошибку и предложит позвонить, а не сделает вид,
что заявка ушла.

## Деплой на РФ-хостинг

Проект собирается в `output: 'standalone'` — Vercel не нужен.

```bash
npm ci && npm run build
# на сервер копируем: .next/standalone, .next/static, public, .env
node server.js            # слушает 3000
```

Дальше systemd-юнит + nginx как reverse-proxy на 3000, сертификат через certbot.
HSTS уже отдаётся приложением, так что HTTPS обязателен.

## Грабли: styled-jsx + Framer Motion

**Важно помнить на будущих проектах.**

styled-jsx скоупит стили, дописывая класс `.jsx-<хеш>` к каждому селектору:
`.nav` в коде превращается в `.nav.jsx-14f8e7` в CSS. Этот класс он проставляет
только обычным HTML-тегам — `div`, `span`, `section`. **Компонентам он его не
проставляет.** А `motion.div`, `motion.header`, `motion.article` — это компоненты.

Итог: любое правило, где в цепочке селекторов участвует motion-элемент, молча
не применяется. Ошибки нет, сборка проходит, в консоли чисто — просто стилей нет.

Здесь так отвалилось около трети вёрстки: шапка (`motion.header`), карточки услуг
(`motion.article`), команда, отзывы, цифры, FAQ. Плюс все правила вида
`.hero h1`, потому что `h1` — это `motion.h1`.

**Как чинили:** блоки переведены в `<style jsx global>`. Проверено, что имена
классов между компонентами не пересекаются (152 класса, 0 конфликтов), поэтому
глобальная область безопасна. Именование остаётся БЭМ-подобным — это и есть
защита от коллизий.

**Как проверять:** открыть страницу и в консоли посмотреть
`getComputedStyle(document.querySelector('.нужный-класс'))`. Если фон/границы
пустые, а в CSS правило есть — скорее всего это оно.

Альтернативы, если понадобится вернуть скоуп: `styled-jsx/css` с `css.resolve`
(даёт className, который вешаешь на motion-компонент руками) или CSS Modules.
